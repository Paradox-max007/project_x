# MANPOWER MANAGEMENT SYSTEM

## 0 → 100 Product Requirements & Development Specification

**Reference:** ASM_PROJECT
**Target architecture:** Next.js + TypeScript + Supabase + Vercel
**Primary users:** Super Admin, Admin/HR/Operations staff
**Future users:** Site Supervisor, Client, Employee/Worker
**Platform:** Responsive Web Application
**Deployment:** Vercel
**Database/Auth/Storage/Realtime:** Supabase

---

# 1. PRODUCT VISION

Build a professional manpower-company management platform for managing:

* Employees/workers
* Employee documents
* Employee assignments
* Client sites/projects
* Team leaders
* Daily attendance
* Overtime
* Employee ratings
* Warnings
* Fines
* Leave requests
* Employee cancellation/deletion requests
* Uniform/PPE distribution
* Notifications
* Administrators
* Role/menu permissions
* Dashboard analytics
* Employee CV/report generation
* WhatsApp sharing
* Audit history
* Secure document storage

The new system should reproduce the important business capabilities of the reference application while being:

1. More secure
2. More scalable
3. Easier to maintain
4. Better structured for Supabase
5. Easier for an AI coding agent to develop
6. Fully responsive
7. Ready for future mobile applications
8. Ready for multiple manpower-company branches
9. Suitable for production deployment

---

# 2. CORE DESIGN PRINCIPLE

Do NOT build the new application as one giant page containing business logic.

Use:

```text
UI
 ↓
Feature Components
 ↓
Application Services
 ↓
Supabase
 ↓
PostgreSQL / Storage / Auth / Realtime
```

Business-critical operations should be performed through:

* PostgreSQL functions
* Supabase RPC
* Server-side actions/API routes
* Database constraints
* RLS policies

The browser must never be trusted for authorization.

# 13. TEAM LEADER

A worker may become team leader for a site.

Rules:

* One active team leader per site
* A team leader must be assigned to that site
* Deactivating a site removes team-leader assignment
* Moving the team leader to another site removes previous leadership
* UI must warn before replacing an existing leader

Database constraint/function should enforce this.

# 26. DELETION POLICY

Never physically destroy important employee history.

When deleted:

```text
Employee = deleted
```

Historical:

* Attendance
* Warnings
* Fines
* Leave
* Uniform
* Site history

remain available to authorized administrators.

This is preferable to the reference project's mixed soft-hide/delete approach.
